# H200 CUDA 12.8 节点上的 GLM-5.2 AutoModel 镜像适配方案

> 记录时间：2026-07-08  
> 目标：在单机 8xH200 上跑 `tests/functional_tests/speculative/run_glm_5.2_smoke.sh`。  
> 当前限制：宿主机 NVIDIA driver 不能升级。

---

## 1. 结论

当前问题不是 GLM-5.2 权重，也不是 smoke 脚本参数，而是 **容器 PyTorch CUDA 版本高于宿主机 driver 能支持的版本**。

已确认现象：

```text
宿主机：Driver 570.133.20 / CUDA 12.8
当前容器：torch.version.cuda = 13.2
错误：The NVIDIA driver on your system is too old
```

因此当前 `nemo-automodel:26.06.00` 这类 `torch_cuda=13.2` 镜像不能在该节点上跑训练。宿主 driver 不能升级时，只能选择：

```text
找或构建一个 torch.version.cuda <= 12.8 的 NeMo AutoModel 运行镜像。
```

不要只看：

```bash
torch.cuda.device_count()
```

因为本次出现过 `device_count=8`，但 `torch.cuda.is_available()=False`，实际无法分配 CUDA tensor。

## 3. 镜像验收标准

候选镜像进入容器后，先不要跑 GLM。只跑下面的 CUDA 验证：

```bash
source /opt/venv/env.sh 2>/dev/null || true

export LD_LIBRARY_PATH=/usr/local/cuda/compat:/usr/local/nvidia/lib64:${LD_LIBRARY_PATH:-}
export PATH=/usr/local/nvidia/bin:$PATH

nvidia-smi -L
python -c "import torch; print('torch=', torch.__version__); print('torch_cuda=', torch.version.cuda); print('available=', torch.cuda.is_available()); print('count=', torch.cuda.device_count()); x=torch.empty(1, device='cuda'); print(x); print(torch.cuda.get_device_name(0))"
```

合格输出必须同时满足：

```text
nvidia-smi -L 能看到 8 张 NVIDIA H200
torch.version.cuda <= 12.8
available=True
count=8
能打印 tensor(..., device='cuda:0')
能打印 NVIDIA H200
```

只要出现下面错误，就不要继续排 GLM：

```text
The NVIDIA driver on your system is too old
```

这说明镜像 CUDA runtime 仍然高于宿主 driver 支持范围。

## 4. 推荐路径 A：找平台已有低 CUDA 镜像

优先问平台是否已有这些类型的镜像：

```text
PyTorch + CUDA 12.8
NeMo AutoModel 26.04 / 26.05 / CUDA12.x
NVIDIA PyTorch 容器 CUDA <= 12.8
```

不要只按镜像名判断，必须进容器跑第 3 节的 CUDA tensor 验证。

找到合格基础镜像后，再确认 AutoModel / DeepEP：

```bash
python -c "import importlib.util; print('deep_ep=', importlib.util.find_spec('deep_ep') is not None)"
test -f tests/functional_tests/speculative/run_glm_5.2_smoke.sh
```

如果 `deep_ep=False` 或 smoke 脚本不存在，继续走路径 B。

## 5. 推荐路径 B：基于 CUDA 12.8 基础镜像构建 AutoModel 环境

适用场景：

```text
基础镜像 CUDA/PyTorch 可用，但没有当前 Automodel 源码、没有 DeepEP、或没有 GLM-5.2 smoke 脚本。
```

原则：

- 使用当前 checkout，而不是依赖镜像自带旧 `/opt/Automodel`。
- 使用 `uv`，不要在文档/脚本里引入 `pip install`。
- 进入 PyTorch 基础容器后，先运行 `docker/common/update_pyproject_pytorch.sh`，避免 `uv sync` 重装 torch 导致 CUDA/TE 版本错配。
- GLM-5.2 MoE 需要 DeepEP/HybridEP，所以 `--extra moe` 不能省。

容器内安装流程：

```bash
cd /opt/Automodel

# 如果 /opt/Automodel 是挂载的当前 checkout，先适配容器内已有 PyTorch。
bash docker/common/update_pyproject_pytorch.sh /opt/Automodel

# all 不包含 moe；GLM-5.2 MoE smoke 需要额外装 moe。
uv sync --locked --all-groups --extra all --extra moe

source /opt/venv/env.sh
```

安装后验收：

```bash
export LD_LIBRARY_PATH=/usr/local/cuda/compat:/usr/local/nvidia/lib64:${LD_LIBRARY_PATH:-}
export PATH=/usr/local/nvidia/bin:$PATH

python -c "import torch, importlib.util; print('torch=', torch.__version__); print('torch_cuda=', torch.version.cuda); print('available=', torch.cuda.is_available()); print('count=', torch.cuda.device_count()); print('deep_ep=', importlib.util.find_spec('deep_ep') is not None); print(torch.empty(1, device='cuda'))"
test -f tests/functional_tests/speculative/run_glm_5.2_smoke.sh
```

合格后再固化成平台镜像，避免每次启动容器都重新编译/安装 DeepEP。

## 9. 怎么判断自己的基础镜像能跑 GLM-5.2

先分清两件事：

```text
基础镜像 CUDA 可用       != 能跑 GLM-5.2
能跑 GLM-5.2 smoke      != 能跑完整 78 层 / TileLang / 32K 长上下文正式 SFT
```

### 9.1 能跑 GLM-5.2 smoke 的最低要求

这次目标是 `run_glm_5.2_smoke.sh`，它跑的是 **单机 8 卡、减层 6 层 target、SDPA attention、torch_mm experts** 的 DSpark smoke。最低要求如下：

| 能力 | 必须 | 验证 |
|------|------|------|
| CUDA/PyTorch 可用 | 是 | 能分配 `torch.empty(1, device="cuda")` |
| 8 张 H200 可见 | 是 | `nvidia-smi -L` + `torch.cuda.device_count()==8` |
| 当前 Automodel 源码 | 是 | 有 `tests/functional_tests/speculative/run_glm_5.2_smoke.sh` |
| GLM-5.2 权重 | 是 | 有 `config.json` / `model.safetensors.index.json` |
| DeepEP/HybridEP | 是 | `importlib.util.find_spec("deep_ep") is not None` |
| TileLang | smoke 不强制 | smoke config 使用 `target_attn_backend: sdpa` |
| grouped_gemm | smoke 不强制 | smoke config 使用 `target_experts: torch_mm` |

也就是说：**你的基础镜像只要 CUDA 12.8 可用，还不代表能跑 GLM-5.2；但只要再补齐当前 Automodel checkout + DeepEP，就有机会跑 smoke。**

### 9.2 一键能力探针

在你的基础镜像容器里执行：

```bash
cd /opt/Automodel
source /opt/venv/env.sh 2>/dev/null || true

export LD_LIBRARY_PATH=/usr/local/cuda/compat:/usr/local/nvidia/lib64:${LD_LIBRARY_PATH:-}
export PATH=/usr/local/nvidia/bin:$PATH

MODEL=/mnt/shared-storage-gpfs2/gpfs2-shared-public/huggingface/hub/models--zai-org--GLM-5.2
HASH="$(cat "$MODEL/refs/main")"
GLM52="$MODEL/snapshots/$HASH"

python -c "import torch, importlib.util; print('torch=', torch.__version__); print('torch_cuda=', torch.version.cuda); print('cuda_available=', torch.cuda.is_available()); print('gpu_count=', torch.cuda.device_count()); print('cuda_tensor=', torch.empty(1, device='cuda')); print('deep_ep=', importlib.util.find_spec('deep_ep') is not None); print('tilelang=', importlib.util.find_spec('tilelang') is not None); print('grouped_gemm=', importlib.util.find_spec('grouped_gemm') is not None)"

test -f "$GLM52/config.json"
test -f "$GLM52/model.safetensors.index.json"
test -f tests/functional_tests/speculative/run_glm_5.2_smoke.sh
python -m pytest tests/unit_tests/speculative/test_dspark_glm_5_2.py -q
```

结果解释：

| 结果 | 判断 |
|------|------|
| `cuda_tensor` 失败 | 基础镜像不合格，先别管 GLM |
| `deep_ep=False` | 不能跑 GLM-5.2 MoE smoke，需要装 `--extra moe` 或换镜像 |
| `run_glm_5.2_smoke.sh` 不存在 | 源码太旧，需要挂载/切到当前 checkout |
| CPU unit test 失败 | 当前源码/依赖不匹配，不能跑 smoke |
| 以上都通过 | 可以尝试 `run_glm_5.2_smoke.sh` |

### 9.3 能跑哪些 GLM-5.2 特性

如果只通过 9.2，通常只能说：

```text
可以尝试 GLM-5.2 DSpark 单机减层 smoke。
```

它覆盖的关键链路：

- GLM-5.2 target 从本地 checkpoint 加载
- FP8 checkpoint 加载后 dequant 到 bf16
- FSDP2 + EP=8
- MoE dispatcher 走 DeepEP/HybridEP
- DSpark 在线捕获 target hidden states
- dense draft 训练并记录 finite loss

它不等于完整覆盖：

- 完整 78 层 GLM-5.2 target
- 多节点 `ep_size=32/64`
- 32K 长上下文 CP
- `backend.attn=tilelang` 的 GLM DSA sparse MLA fused kernels
- grouped_gemm / gmm expert backend

### 9.4 如果你想验证 TileLang/正式 GLM-5.2 SFT

那是更高一档，需要额外检查：

```bash
python -c "import importlib.util; print(importlib.util.find_spec('tilelang') is not None); print(importlib.util.find_spec('tile_kernels') is not None)"
python -c "import transformer_engine; print(transformer_engine.__version__)"
```

并且需要跑对应的正式 recipe，而不是 smoke：

```text
examples/llm_finetune/glm/glm_5.2_tulu3_4k_tilelang_100k.yaml
examples/llm_finetune/glm/glm_5.2_tulu3_32k_tilelang_cp8.yaml
```

这些路径通常不是单机 H200 目标，涉及多节点、EP=64、PP=4、CP=8 等配置。

## 10. 不建议继续尝试的方向

- 不要继续在 `torch.version.cuda=13.2` 的容器里调 `LD_LIBRARY_PATH`；它只能修 `nvidia-smi` 找不到库，不能解决 driver API 不兼容。
- 不要把 `torch.cuda.device_count()==8` 当成成功；必须能分配 `torch.empty(..., device="cuda")`。
- 不要直接跑全量 `examples/speculative/dspark/glm_5.2_dspark.yaml`；单机 H200 先跑减层 smoke。
- 不要在镜像自带旧 `/opt/Automodel` 里硬跑；如果没有 `run_glm_5.2_smoke.sh`，必须切到当前 checkout。
